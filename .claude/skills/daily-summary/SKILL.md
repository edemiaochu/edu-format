# 每日工作总结

把今天的工作整理成 Markdown 报告，保存到当前目录下的 `daily-summary/YYYY-MM-DD.md`。

## 执行步骤

### 1. 确定日期

默认今天（`date +%F`）。用户在参数里指定了日期就用指定的。

### 2. 收集事实材料（不要只凭记忆）

依次执行，结果允许为空——本仓库经常长期无 git 提交，`git log` 空输出是正常的：

```bash
# 今日 git 提交
git log --since="today 00:00" --pretty=format:"%h %ad %s" --date=format:"%H:%M" --stat

# 工作区状态（未跟踪/已修改的文件）
git status --short

# 今天改动过的文件（排除噪声，最多 60 个；文件多时只保留代表性的并记总数）
find . -type f -mtime 0 -not -path "*/node_modules/*" -not -path "*/.git/*" -not -path "*/.claude/*" -print | head -60
```

### 3. 结合会话上下文

上面的材料只说明"什么变了"；"为什么变、结论是什么"来自当前会话的对话内容，整理出：

- 今天完成的任务：用户提出的问题 + 最终解决结果
- 关键数字与结论（如：扫描出多少标识符、映射多少条、修了哪些 bug、diff 多少）
- 踩过的坑和解决办法（简短，一条一行）
- 没做完、下一步要做的事

### 4. 写入文件

- 路径：`daily-summary/YYYY-MM-DD.md`（文件夹不存在就先创建）
- **文件已存在时先 Read 原文，把新内容合并进对应小节再写回，不要盲目覆盖**——同一天可能多次调用
- 按此模板（小节按需增减）：

```markdown
# YYYY-MM-DD 工作总结

## 今日完成
- …（做了什么 → 结果）

## 关键改动
- `文件名` — 改了什么、为什么

## 数据与结论
- …（具体数字）

## 问题与解决
- …（坑 + 解法）

## 待办 / 下一步
- [ ] …
```

## 原则

- 事实优先、简洁：每条写"做了什么 → 结果"，不写空话
- 数字要具体（"7344 个标识符"、"7027 条映射"），不写"很多/大量"
- /tmp 临时产物、测试用中间文件不算工作内容，不写入总结
- 总结用中文
